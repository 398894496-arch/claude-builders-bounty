# CLAUDE.md — Next.js 15 + SQLite SaaS

> Opinionated, production-ready. Drop into any greenfield Next.js 15 App Router
> project with SQLite (better-sqlite3 or Turso) and start shipping.

## Stack & Versions (locked)

| Layer | Choice | Why |
|-------|--------|-----|
| Framework | Next.js 15 App Router | RSC + streaming + file-based routing |
| Language | TypeScript 5.x (strict) | Type safety, not optional |
| Database | SQLite via better-sqlite3 (local) or Turso (edge) | Zero infra, single file, fast |
| ORM | Drizzle ORM | SQL-first, lightweight, great TS support |
| Auth | Lucia Auth v3 (deprecated → use Better Auth) | Session-based, no vendor lock-in |
| Styling | Tailwind CSS v4 + shadcn/ui | Utility-first, copy-paste components |
| Validation | Zod | Parse once, trust everywhere |
| Payments | Polar.sh | Open source friendly, handles tax |
| Runtime | Node.js 22 LTS | Latest stable, built-in SQLite client |
| Package manager | pnpm | Strict, fast, disk-efficient |

**Never add without a reason.** Every dependency costs maintenance budget.

## Naming Conventions

```
Files:
  kebab-case.ts           # ✅ always
  camelCase.ts            # ❌ never for files
  CLIENT_COMPONENT.tsx    # ❌ unless it's a config file

Components:
  PascalCase.tsx          # ✅ React components
  UserAvatar.tsx          # ✅ descriptive, one component per file
  Avatar.tsx              # ✅ ok if it's the only Avatar

Functions:
  camelCase()             # ✅ user-defined functions
  getUserById()           # ✅ verb-first: get, create, update, delete
  handleSubmit()          # ✅ event handlers prefixed with "handle"

Database:
  snake_case columns      # ✅ SQL convention — id, user_id, created_at
  camelCase columns        # ❌ mismatches SQL ecosystem

  Tables: plural           # ✅ users, projects, api_keys
  Join tables: a_b         # ✅ project_members, user_roles
```

## Database Rules

### Migrations — THE RULES

```bash
# 1. Edit schema.ts FIRST — never edit migration files directly
# 2. Generate migration:
pnpm db:generate         # drizzle-kit generate
# 3. Review the generated SQL — it's your responsibility
# 4. Apply:
pnpm db:migrate          # drizzle-kit migrate
```

**⚠️ NEVER:**
- `DROP TABLE` in a migration — rename instead, drop in next deploy cycle
- Edit a deployed migration — add a new one on top
- Run migrations without reviewing the SQL
- Add a column without a default value (or make it nullable)

### Query Patterns

```typescript
// ✅ Prepared statements (better-sqlite3)
const getUser = db.query.users.findFirst({
  where: eq(users.email, sql.placeholder('email'))
});

// ✅ Always limit + paginate lists
const list = await db.query.projects.findMany({
  where: eq(projects.userId, userId),
  limit: 20,
  offset: 0,
  orderBy: desc(projects.createdAt),
});

// ❌ SELECT * without limit
db.query.users.findMany(); // could return 100k rows

// ❌ Raw SQL unless you have a great reason
db.run(sql`DELETE FROM users WHERE id = ${id}`); // prefer Drizzle API
```

## Component Patterns

### Server Component First (default)

```typescript
// ✅ Start here — server component by default
// src/app/(dashboard)/projects/page.tsx
import { db } from '@/lib/db';
import { auth } from '@/lib/auth';

export default async function ProjectsPage() {
  const session = await auth();
  const projects = await db.query.projects.findMany({
    where: eq(projects.userId, session.user.id),
    limit: 50,
  });
  return <ProjectList projects={projects} />;
}
```

### Client Component — only when you need interactivity

```typescript
'use client';
// ✅ Mark client boundary only when needed:
//   - useState / useEffect / useReducer
//   - Event handlers (onClick, onSubmit)
//   - Browser APIs (localStorage, geolocation)
//   - Third-party client libraries (motion, chart.js)
```

### Data Fetching

```typescript
// ✅ Server Component: fetch directly
const data = await db.query.items.findMany();

// ✅ Server Action: mutate data
async function createProject(formData: FormData) {
  'use server';
  const session = await auth();
  if (!session) throw new Error('Unauthorized');
  // ... validate + insert
}

// ❌ useEffect + fetch() for data that the server can provide
// ❌ API route + client fetch when a Server Action works
```

## Forms — The Pattern

```typescript
// 1. Schema (Zod) — src/lib/validations.ts
export const createProjectSchema = z.object({
  name: z.string().min(1).max(100),
  description: z.string().max(500).optional(),
});

// 2. Server Action — src/actions/projects.ts
'use server';
export async function createProject(formData: FormData) {
  const session = await auth();
  if (!session) redirect('/login');

  const parsed = createProjectSchema.parse(Object.fromEntries(formData));
  await db.insert(projects).values({
    ...parsed,
    userId: session.user.id,
  });
  revalidatePath('/projects');
}

// 3. Client Form — submit via action prop
export function CreateProjectForm() {
  return (
    <form action={createProject} className="space-y-4">
      <Input name="name" required />
      <SubmitButton>Create</SubmitButton>
    </form>
  );
}
```

## Anti-Patterns → What We Don't Do (and Why)

| Anti-pattern | Why not |
|--------------|---------|
| `any` type | Destroys type safety. Use `unknown` + Zod parse. |
| `useEffect` for data fetching | Server Components handle this. useEffect is for browser sync. |
| `// TODO` without a ticket | TODOs rot. File an issue or just do it. |
| Nested ternaries | Nobody can read them. Extract to a function with a name. |
| `isLoading` boolean | Use Suspense boundaries instead. |
| API route wrapping a DB call | Server Actions are simpler and typesafe. |
| `export default` for utilities | Named exports are tree-shakeable and grep-friendly. |
| `console.log` in production | Use a logger (pino) with levels. |
| Hardcoded strings in JSX | Extract to constants or i18n keys. |
| `.env` committed to git | Use `.env.example` with fake values. |

## When in Doubt

1. **Do the simplest thing that works.** Don't over-engineer for "future scale."
2. **Server Components first,** `'use client'` only when you must.
3. **One component, one job.** Extract when it grows beyond one screen.
4. **SQLite is a real database.** Indexes, transactions, WAL mode — use them.
5. **Auth is always the first thing you check.** If a query should be scoped to a user, scope it.
